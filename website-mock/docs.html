Publish (My Tawala → Library)

Deliberate bridge from private My Tawala into the one public Library. Entry points: Project Details PUBLISH (listing Publish removed Aug 9 — lean list), or library-admin.html.

  • Rename on the way in (strips any " (stub)" suffix by default).
  • Optional replace target: stub → retires to My Tawala (kept marked stub); non-stub → in-place overlay.
  • Purges :8080 responses by default (owner Aug 1, 2026 — one account must never see another's submissions). "Purge responses when publishing" checkbox, default checked, calls TawalaDemo.purgeAfterPublish (same path as My Tawala Purge) right after a successful Publish. Publish still succeeds if purge is skipped (no linked deploy) or fails — the success alert adds a ⚠️ line instead. Does not run on Retire, Rename, or a category move.
  • Mock storage only (localStorage). Shipping into js/demo-urls.js + liveReady: true is a separate maintainer step.

Smoke: mytawala.html → open a project → PUBLISH on Project Details → confirm → check library.html and My Tawala for the expected add / retire / replace outcome, plus a purged-row count (or a clear ⚠️ skipped/failed note) in the same success alert.

Library admin

Maintainer tools so rename / overwrite / retire do not require an agent. Open library-admin.html.

  • Enable once via ?admin=1 or the on-page button (sets tawala.mock.libraryAdmin).
  • Publish / overwrite from any My Tawala project (same purge-on-publish default as above).
  • Rename any Library display name in place.
  • Retire removes from public Library but always keeps a My Tawala safety copy (no public Library Delete).
  • Restore to Library undoes a retirement when that id is still free.

Quiet links also live in the Library and My Tawala sidebars (Maintainer tools).

Export / Import

Data only — Excel-shaped response submissions for the current project. Import restores messed-up data; field mismatch fails; Import does not roll back the project definition.

  • Export — downloads <slug>.export.json (no confirm).
  • Import — pick that file → field check → confirm → replace submissions.
  • Needs designer-web API on :3001 and a project with a resolvable uniqueId.

UI: My Tawala listing or Project Details. API smoke (with a real uniqueId): 

curl -s -X POST http://localhost:3001/api/export-responses \
  -H 'Content-Type: application/json' \
  -d '{"uniqueId":"<uniqueId>","credentials":{"user":"dev","password":"dev"}}' \
  > /tmp/export.json

Full round-trip script: README § My Tawala layout → Smoke Export/Import.

Backup / Restore

Paired snapshot — mock .backup.json carries catalog properties + response data + (when available) project definition JSON from website-mock/projects/. Distinct from Export/Import.

  • Backup — download, no confirm.
  • Restore — confirm → re-apply properties, then data. Does not push definition into a live Designer session (:5173 and :5500 do not share storage).

Real Java Backup is a .backup ZIP; this mock uses JSON for local ops.
